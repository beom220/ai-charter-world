## 1. 로컬 데이터 초기화 (안전 최우선)

기존 세계관 및 캐릭터는 개발 테스트 데이터이므로 삭제하고 새 배경 규칙에 맞춰 다시 만든다.

- **먼저 DB 접속 대상이 해당 사용자의 전용 로컬 개발 PostgreSQL인지 검증**한다. 원격·공유·운영·판별 불가능한 DB면 **절대 삭제하지 않고**, 구현을 이어가되 보고에 명시한다. 데이터 삭제 전 대상 World/Character 개수와 대상 목록을 출력한다.
- 개발 서버 및 RunnerHost가 실행 중이면 종료하고, 신규 장면 생성 및 동시 쓰기를 막는다.
- 삭제 대상: `World` 및 소속 `Character`, 장면/발언, 감정·관계·기억 및 이력, GameState, Runtime/Run, 세계별 사건·SSE 연결·Outbox, 수동/자동/RECOVERY 세이브 등 **World 소유 데이터만**. 현재 Prisma 모델 및 FK를 확인해 실제 이름·종속 관계대로 처리한다.
- **보존 대상**: User, Better Auth 계정·세션, Google OAuth, ProviderConnection, 암호화 Gemini API 키 및 모델 설정, UsageGuard/호출 내역, breaker, Prisma migration history, 코드/Git. 타 사용자 또는 다른 DB의 데이터는 건드리지 않는다.
- DB 전체 reset/drop/truncate cascade 금지. 가능하면 안전한 원자적 트랜잭션 및 기존 관계 삭제 정책 활용. 삭제 후 World/Character 0개와 보존 대상 수/레코드 무변경 확인.
- 안전 조건을 만족할 수 없으면 초기화만 생략한다. **보안 정보를 출력하거나 삭제하지 않는다.**

## 2. 나이·선택 규칙

- **유년기(CHILDHOOD): 모든 신규 캐릭터 필수**.
- **성년기(ADULTHOOD): 캐릭터 나이 19세 이상이면 필수; 18세 이하는 설정 불가**.
- 사용자는 아래 고정 프리셋에서만 선택. **직접 입력·미설정 선택지·새 배경 자동 작성 금지**.
- 캐릭터 수정 시 변경 가능. 나이를 19세 이상→18세 이하로 내리면 성년기 ID를 제거; 18세 이하→19세 이상이면 성년기 선택을 요구한다. 클라이언트뿐 아니라 서버도 엄격 검증.
- DB 필드는 기존 데이터/구버전 세이브 호환성을 고려해 nullable로 둘 수 있지만 **신규 생성 및 사용자 수정 요청에서 필수 검증 예외는 없다**.
- 배경은 과거 경험이며 현재의 성격·선택·능력을 강제로 결정하는 스탯이 아니다.

## 3. 프리셋 단일 소스

## 4. 랜덤 생성

유년기·성년기 각각 **등급을 먼저 가중 추첨**: COMMON 60%, UNCOMMON 30%, RARE 10%, 이후 해당 등급 내 균등 선택. 기존 캐릭터 전체 랜덤 생성 및 필드 잠금과 연계. 유년기 항상 선택, 성년기는 19세 이상만 선택. 나이 변경과 잠금의 충돌 시 서버 나이 규칙을 우선하며 UI에 명확히 처리. 각 배경 개별 랜덤 버튼 제공. 추가 Gemini 호출 금지.

## 5. UI 및 API

- 기존 캐릭터 생성·수정 폼에 게임형 프리셋 선택 추가: 일반/특수/희귀 탭·카드 또는 모달, 명칭/설명 미리보기, 선택 강조, 랜덤, 필수 안내. 44개를 한 번에 길게 나열하지 않기. 모바일 및 현행 디자인 대응. 캐릭터 상세 프로필에서 두 배경 확인.
- 18세 이하 성년기 선택 불가; 나이 입력 변화 즉시 반영. 필수 선택 전 저장 불가. **사용자 자유 텍스트 입력란 금지**.
- Prisma `Character`에 배경 ID 최소 필드 추가, **새 migration** 작성(기존 migration 수정 금지). CRUD 및 랜덤 생성 API·DTO/검증 수정. 잘못된 ID, 연령 미충족, 필수 누락 거절. 기존 인증/소유권·세계당 최대 6명 제약 유지.
- 로컬 삭제 여부와 무관하게 DB가 기존 nullable 캐릭터를 조회·렌더링하는 호환성은 유지한다. 신규/수정 요청에 필수 정책 적용.

## 6. Gemini Context Builder

기존 1장면=1회 Gemini 호출을 유지하면서 프롬프트의 캐릭터 소개에 선택된 프리셋 **이름+설명** 추가. 배경은 지식과 가치관에 영향을 주는 과거 경험일 뿐, 성격·감정·기억·관계나 세계관 제약보다 우선하여 현재 행동을 강제하지 않는다. 배경을 매 장면 기계적으로 반복 설명하지 않고, 과거 사건을 새 현재 사건으로 둔갑시키지 않는다. 새 LLM 호출·출력 스키마 변경 금지.

## 7. Phase 6 세이브/로드

새 세이브에 배경 ID를 포함하고 복원 시 보존한다. **기존 v1 스냅샷의 checksum 및 읽기 호환성**을 깨뜨리지 말 것. 필요하면 명확하게 버전 분기하여 구버전 정상 복원. 기존 수동 5/자동 5/RECOVERY, 1시간 자동 저장, 원자성 및 fencing 유지. 로컬에서 저장 데이터를 삭제하더라도 코드는 버전 호환성을 유지.

## 8. 검증 및 범위

검증: 44종 프리셋 ID·개수·등급, 18/19세 경계, 필수/잘못된 ID/API, 나이 변경, 랜덤 가중치 순수 함수 및 잠금, 기존 nullable 호환, Gemini 컨텍스트, 새·기존 스냅샷 복원, 인증/소유권. **관련 단위·통합 테스트와 typecheck/lint만**, 전체 테스트·반복 빌드·변이 테스트·실제 Gemini API 호출 금지. 관련 없는 리팩터링 금지.

**미구현**: 스탯/스킬, 능력치 보너스, 세계관별 배경 생성, 사용자 자유 입력, 랜덤 사건, 유저 지정 사건 및 캐릭터 명령 UI(현재 존재하지 않으며 Phase 7-2/7-3 계획), Runner 변경.
