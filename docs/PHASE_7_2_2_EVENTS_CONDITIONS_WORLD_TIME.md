## 0. 구현 전 현황 파악 — 기존 월드 시간 확인 필수

현재 보고서에서 `GameState.nextSceneSeq`와 사건의 장면 기준 계산은 확인되지만, **월드 내부 날짜/시각이 이미 구현됐는지는 확인되지 않았다.** 코드 및 DB에서 월드 시각, 게임 시간 누적, Runner PAUSE/RESUME, 실행 속도, scene timestamp, save/load 처리를 먼저 조사하고 결과를 보고한다. 기존 구현이 있다면 중복 시계를 만들지 말고 호환되게 확장한다.

**사용자 요구:** 실제 **1시간 = 월드 1.5일(36시간)**. 따라서 실시간 1초 = 월드 36초, 실시간 1분 = 월드 36분. **월드가 RUNNING으로 실제 진행한 시간에만 흐르며**, PAUSED/IDLE/중단/클라이언트 연결 해제에 따른 자동 일시정지 상태에서는 흐르지 않는다. 실제 브라우저를 끄고 정지된 시간으로 부상·사망을 진행시키지 않는다.

시간은 서버/DB가 권위 있는 값이어야 하고, 클라이언트의 JS 타이머나 시스템 로컬 날짜만으로 판정하지 않는다. 기존 실행 속도 설정과의 관계를 조사하고 **중복 가속을 피한다**: 기본 월드 시간 배율은 36×, UI의 장면 생성 간격(속도) 변경이 시간 배율을 의도치 않게 또 곱하지 않도록 구분한다. 기존 속도 정의와 충돌한다면 변경 지점을 명시한다.

## 1. 월드 시간 설계·구현

- `GameState`에 월드 시간의 **기준 시점/누적 경과 시간**을 최소 필드로 추가한다. 월드 날짜/시각은 안정된 게임 내 시작 시점 + 누적 진행 시간으로 도출할 수 있다. 별도의 장면 카운터와 구별한다.
- 실제 RUNNING 구간의 서버 기준 경과 시간 ×36을 월드 누적 시간에 반영한다. **일시정지, 종료, 연결 끊김, lease 교체, 서버 재시작**에서 이중 계산 또는 정지 시간 누적이 없어야 한다. 크래시 복구 시 마지막으로 **영속화된 활성 구간**까지만 안전하게 계산하고 미래/긴 오프라인 구간을 소급하지 않는다.
- 장면을 정상 커밋할 때 해당 시점의 **worldTime**을 장면과 상태 변화 기록에 일관되게 남기거나, 동일한 결과를 재구성할 수 있는 영속 필드를 제공한다. 실패/펜싱된 호출은 사건·부상·사망·회복을 커밋하지 않는다. 실행 시간이 커밋 전후 상태에 반영되는 방식은 결정적으로 정의한다.
- 사건 발생 시각, 캐릭터 상태 지속 시간, 자연 회복 기준에 월드 시간을 사용한다. **자동 사건 추첨의 20장면 단위 규칙은 변경하지 않는다.** 장면 수와 월드 시간은 별도 축이다.
- UI에서 현재 **월드 날짜와 시각**, 가능하면 '월드 1일 = 실제 40분(진행 중)'을 표시한다. 폴링/SSE 및 재연결에서도 값이 뒤로 가지 않도록 한다. 정확한 시간대/달력 표현은 세계관 자유도를 해치지 않게 단순한 `Day N, HH:MM`을 기본으로 한다.
- 저장/불러오기에 누적 월드 시간·상태 변화 시각을 포함하고, 과거 v1/v2/v3 스냅샷은 결정적 기본값으로 호환한다. **기존 v3의 의미와 체크섬을 변경하지 말고 필요 시 v4 + v3→v4 마이그레이터**를 추가한다. recovery/rolling/manual save의 정합성을 보장한다.

## 2. 캐릭터 상태 체계 변경 — 원인과 심각도를 분리

기존 7-2-1의 `ThermalState NORMAL/COLD/VERY_COLD/HOT/VERY_HOT`, `InjurySeverity NONE/MILD/MODERATE/SEVERE/CRITICAL`은 이번 요구와 정확히 일치하지 않는다. **기존 저장 데이터가 유실되지 않는 단방향 마이그레이션**으로 다음 구조를 표현한다.

### 2.1 온도 불편

- `온도 원인`: 없음/추위/더위.
- `심각도`: 없음/**경미/심함/극심**.
- 화면에는 예: **더움(경미)**, **더움(심함)**, **더움(극심)**, **추움(경미)**, **추움(심함)**, **추움(극심)** 으로 표시한다. 정상일 때는 정상.
- 추위와 더위를 동시에 같은 사람에게 표시하지 않는다. 기존 `COLD`→추움(경미), `VERY_COLD`→추움(심함), `HOT`→더움(경미), `VERY_HOT`→더움(심함) 등 보수적 매핑으로 기존 상태를 보존한다. **극심 단계는 신규**이며 서버가 확정한 변화에만 진입한다.
- 기상·환경·장소·대피·난방·냉방 등 장면 결과에 따라 악화/개선 가능. 한 장면에서 일반적인 이유 없이 여러 단계 점프하지 않도록 하고, 특별한 재난/명시적 결과는 예외를 엄격히 검증한다.

### 2.2 부상과 고통

- `부상 정도`와 `체감 고통`은 **서로 독립**된 상태로 보존한다. 부상이 없어도 극심한 온도나 질병으로 고통이 생길 수 있고, 치료/진통으로 고통만 먼저 완화될 수 있다.
- **고통** 역시 `없음/경미/심함/극심` 3단계로 표시: **고통(경미)**, **고통(심함)**, **고통(극심)**. UI에 기존 부상(약간 아픔/아픔/매우 아픔/위독)도 별도로 표기할 수 있다.
- 폭행·맹수/동물 공격·낙상·재난·질병 등에서 **실제 피해가 장면에 일어났을 때만** 부상/고통 변화를 제안하고 적용한다. 사건의 단순 등장이나 '공격할 거야'라는 대사만으로 부상 확정 금지.
- 기존 `CharacterCondition`, `CharacterConditionChange`와 외래키/제약/체크섬/세이브 호환을 보존하며 꼭 필요한 필드만 추가. 상태 원인·마지막 변화 **월드 시각**·지속 누적 시간, 치료 효과 기록을 추적한다.

## 3. 극심 상태의 누적 악화와 사망

- **극심한 더위/추위/고통이 지속될 경우 사망까지 이어질 수 있어야 한다.** 다만 극심 진입 즉시 사망하거나 **극심 하나만으로 매 장면 무작위 즉사**하게 만들지 않는다.
- 단계 진행은 서버의 **월드 시간 누적 + 실제 환경/부상 상태 + 치료·보호 조치**에 기반한다. 자연 회복/악화 판정은 정상적으로 진행된 월드 시간과 커밋된 장면에서만 확정한다. 상태 변화가 없는 동안 임의로 상태가 치솟지 않도록 원인/노출 지속을 검증한다.
- 모델이 제안하는 사망은 **실제 장면의 치명적인 결과** 또는 **지속된 극심 상태 및 적절한 전조/악화**가 서버에서 확인될 때만 허용한다. '극심이 오래되었다'만으로 실시간 타이머에서 즉시 사망 처리하지 말고, **서버가 판정하는 생명 위험 조건**을 충족한 뒤 다음 정상 장면 커밋에서 결정적으로 반영한다.
- 수치는 `config/limits.ts` 등에 중앙화한다. 구체 위험 임계치가 미합의이므로 **MVP용 보수적 초깃값을 코드/문서에 명시**하고 테스트 가능하게 한다(실제 의학적 기준이라고 주장하지 말 것). 지나치게 짧은 경과만으로 사망하지 않도록 한다. 원인 해소/치료 시 누적 극심 노출을 해제하거나 감소시켜 회복 가능하게 한다.
- 자연 회복은 치료와 중복 적용하지 않는다. 기존 7-2-1의 4/10/20 **장면 기반 부상 회복 규칙**을 어떻게 월드 시간으로 옮길지 명확히 결정한다. **하나의 회복을 장면 수와 월드 시간으로 두 번 적용하지 말 것.** 권장: 자연 회복/열 노출/사망 위험은 월드 시간 기준으로 통일하고, 장면은 결과 확정 트리거만 담당. 기존 세이브 및 테스트에 대한 마이그레이션도 포함한다.
- 실제 치료 수행, 따뜻한 대피소/냉각, 구조·응급처치 등의 장면 결과가 있으면 단계적으로 개선될 수 있다. 계획/발언만으로 치료 성공 확정 금지.
- 기존 사망 불변식 유지: DEAD 이후 발화·참가·기억·감정·상태 변경 금지, 사망 원인/시각 기록, 사망해도 최대 6 캐릭터 슬롯 점유, 과거 대화 보존, 살아있는 대화 가능 캐릭터 2명 미만이면 새 장면 생성 중단. 사망한 캐릭터의 시점 이후 장면에 음성이 등장하지 않도록 스키마/서버에서 검증한다.

## 4. Phase 7-2-2 자동 사건·장면 생성 연결

- **기존 자동 사건 프리셋 24개와 DB 영속 구간 결정**을 재사용. 장면 #3부터 구간 #3~#22, #23~#42… 별로 **구간당 40% 한 번 추첨**하고 구간 안 예약 장면에서 자동 사건을 발생시킨다. **매 장면 40%가 아님.**
- 여러 자동 사건은 물론 이후 사용자 사건도 동시에 ACTIVE 가능. ACTIVE 사건은 발생 오래된 순서로 제공하며 캐릭터들은 해결을 목표로 대화/행동한다. 즉시 위험은 우선 대응 가능하고 오래된 미해결 사건은 유지. **장면 수 만으로 강제 종료 금지.** 해결·실패·타협 등의 구체적 결과가 있을 때만 원자적으로 RESOLVED.
- 프롬프트: 현재 월드 `Day N HH:MM`, 진행 중 사건 목록(오래된 것 먼저), 캐릭터별 온도 불편(원인/단계), 부상/고통, 생존 상태, 치료·회복 목표를 간결하게 제공. Gemini 기존 **장면당 1회 호출만** 사용.
- 구조화 출력: 사건별 해결 제안, 환경/고통/부상/치료/사망 제안을 검증하고 **기존 장면·발언·기억·감정·관계와 동일한 커밋 트랜잭션**에서 원자적으로 처리. 실패/재시도/펜싱 실패 시 사건/건강 상태 롤백.
- `eventOutcome` 누락이나 잘못된 필드 때문에 **실제로 시작된 사건을 DB에 기록하지 못하는 상태**가 되어서는 안 된다. 서버의 안전 기본값(미해결/프리셋 설명)을 사용한다. 한 사건 ID를 다른 사건으로 잘못 해결 금지.
- 사망자는 다음 장면 참가자 후보에서 제외하고, Gemini가 사망자 발화를 제안하면 서버가 거부/안전하게 처리한다. 기존 다중 참가자·발화·SSE·세이브 복원 로직을 깨지 않는다.
- SSE/대화 UI에 사건 발생·진행·해결 배너와 현재 월드 시간, 캐릭터 패널에 온도/통증/부상/생존 표시. 메신저형 말풍선에는 기존대로 캐릭터 대사만 표시.
- **사용자 사건 API/모달/취소는 7-2-3에서 구현**하므로 지금 하지 않는다.

## 5. 동시성, 보존, 검증

- 기존 World→Runtime 잠금 순서, `settingsSeq`, `stateVersion`, `attemptId`, lease, outbox, UsageGuard, Run 제약을 보존한다.
- `WorldEventPeriod`의 추첨 판정 중복 방지 및 자동 사건 단일 커밋을 검증한다. 저장/불러오기 후 월드 시간·노출 누적 시간·고통/부상/생존/사건 상태가 정확히 복원되어야 한다.

- 사망은 비가역 사건이지만 세이브 복원으로 과거 상태로 돌아갈 수 있다는 기존 복원 정책은 유지한다. 과거 상태로 복원 후 원래 죽었던 캐릭터가 살아 있어도 시간/기억/장면 참조 일관성을 보장한다.
- 관련 unit/integration + DB migration-replay/scope-matrix/snapshot v1·v2·v3→최신 호환, `pnpm typecheck`, `pnpm lint` 실행. 전체 빌드/전체 테스트 반복/실제 Gemini 호출은 하지 않는다.
- 테스트 항목: 시간 배율(실제 1h→월드 36h), 진행 중만 시간 이동, 상태별 경미/심함/극심 표시, 극심 지속/해소와 사망 위험, 치료 및 자연 회복, 사망자 참가/슬롯 불변식, 자동 사건 구간/해결/중복 방지, 펜싱 실패 시 상태 무변경.
