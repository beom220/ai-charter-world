# Phase 7-4 — 대화창 사건·상태 변화 UI 개선

현재 최신 커밋을 기준으로 진행한다.

이번 작업은 대화창의 사건·상태 변화 메시지를 개선하는 것이다. **UI 표현 계층만 수정**하고 게임 로직이나 DB는 변경하지 않는다.

## 1. 말풍선 디자인

기존 캐릭터 대사 말풍선은 수정하지 않는다.

사건·상태 변화·사망 메시지는 말풍선 형태를 유지하고 다음 디자인을 적용한다.

| 메시지 유형 | 테두리 색상 | 배경 |
|---|---|---|
| 자동·사용자 사건 | 파란색 `#3B82F6` | `#FFFFFF` |
| 긍정적 변화 | 초록색 `#22C55E` | `#FFFFFF` |
| 부정적 변화 | 주홍색 `#F97316` | `#FFFFFF` |
| 캐릭터 사망 | 검정색 `#171717` | `#FFFFFF` |

- 배경은 완전히 불투명한 흰색이다.
- 테두리는 1~2px, 모서리는 기존 말풍선과 어울리게 둥글게 처리한다.
- 메시지는 대화창 중앙에 정렬한다.
- 너비는 내용에 맞추되 모바일에서 넘치지 않게 최대 너비를 제한한다.
- 불필요한 그림자, 그라데이션, 큰 아이콘은 사용하지 않는다.
- 자동 사건과 사용자 사건은 구분하지 않고 동일한 디자인을 쓴다.

## 2. 문구 및 헤더

대화 피드의 사건·상태 메시지에서 아래 기술적인 접두어와 헤더를 제거한다.

- `시스템`
- `사용자가 일으킨 사건`
- `사건 발생`
- `새로운 사건`
- `세계의 변화`

별도 제목이나 라벨을 붙이지 않고 메시지 본문만 표시한다.

표시 예시:
- 사건: `거대한 곰이 야영지 근처에 나타났다.`
- 악화: `한서윤: 고통(심함) — 말라리아 감염으로 인한 고열과 두통`
- 호전: `한서윤: 고통(경미) — 치료 후 통증이 완화되었다.`
- 사망: `한서윤이 사망했다.`

상태 단계와 원인 등 중요한 정보는 삭제하지 않는다.

## 3. 메시지 분류

문자열 키워드 검색보다 기존 이벤트 유형과 실제 이전/이후 상태 변화 데이터를 우선하여 분류한다.

- 사건 발생 → 파란색
- 치료·회복·고통 완화·긍정적 감정 변화 → 초록색
- 부상·고통 증가·추위/더위 악화·부정적 감정 변화 → 주홍색
- 사망 → 언제나 검정색

사망 메시지는 다른 변화보다 우선해 검정색으로 표시한다. 긍정과 부정이 동시에 발생하면 메시지를 분리해 각각 올바른 테두리를 적용한다.

현재 감정 변화가 별도 시스템 메시지로 출력되지 않는다면 새로운 메시지를 만들지 않는다. 기존에 표시되는 감정 코드(`ANXIOUS`, `FEARFUL` 등)는 사용자 친화적인 한국어로 표시한다.

## 4. 과거 기록 및 실시간 반영

- 과거 저장된 장면과 SSE 실시간 장면을 동일한 컴포넌트/분류 규칙으로 렌더링한다.
- 과거 기록에 저장된 기술적 접두어는 **화면에서만** 정리한다. 원본 DB 기록은 수정하지 않는다.
- 사건·상태 변화·캐릭터 대사 순서를 유지한다.
- 기존 타이핑 애니메이션, 자동 스크롤, 캐릭터 대사 및 행동 서술을 유지한다.
- 긴 한국어 문장과 모바일 화면 너비를 고려해 줄바꿈을 처리한다.

## 5. 변경 금지 범위

- Gemini 프롬프트 및 응답 스키마
- 사건 생성·기억·신체 상태 판정
- 월드 시간
- DB 및 스냅샷·세이브
- 사용자 사건 등록 API
- 캐릭터 대사 말풍선의 기존 디자인

## 6. 검증 및 완료 보고

관련 UI 테스트·typecheck·lint만 실행한다. 실제 Gemini 호출, 전체 빌드 반복, 관련 없는 기능 변경은 하지 않는다.

확인할 사례:
1. 자동/사용자 사건 → 파란 테두리
2. 치료/회복 → 초록 테두리
3. 부상/고통/체온 악화 → 주홍 테두리
4. 사망 → 검정 테두리
5. 과거 기록과 SSE 신규 장면의 표시 일치
6. 기술적 접두어 미표시
7. 모바일 너비 및 긴 문장 줄바꿈

완료 후 변경 파일, UI 변경 전후 예시, 테스트 결과, 커밋 해시를 간결하게 보고한다.
