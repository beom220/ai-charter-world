# AI Character World — 캐릭터 일러스트 및 고정 프로필 영역 구현 지시문 (개정본)


## 1. 준비된 이미지

- 여성 일러스트: `female-01` ~ `female-17` (17종)
- 남성 일러스트: `male-01` ~ `male-06` (6종)
- 총 23개 캐릭터 유형, 유형당 8개 표정, 총 **184개 WebP** 이미지
- 예상 디렉터리: `public/characters/{avatarId}/{expression}.webp`
- 표정 파일명: `neutral`, `happy`, `hopeful`, `sad`, `anxious`, `angry`, `embarrassed`, `tired`
- 이미지 규격: 512×512, 투명 배경
- **보유한 이미지만 사용**한다. 임의로 이미지를 생성하거나 다른 이미지로 바꾸지 않는다. 실제 폴더 구조·파일 수·포맷·해상도를 확인하고 불일치는 보고한다.

## 2. 화면별 이미지 정책 — 가장 중요

| 위치 | 이미지 종류 | 상태 변화 반영 여부 |
| --- | --- | --- |
| 캐릭터 생성·편집 화면의 선택 목록 및 미리보기 | **항상 `neutral.webp`** | **반영하지 않음** |
| **대화창의 개별 대사 옆 프로필** | **항상 `neutral.webp`** | **반영하지 않음** |
| **새로운 고정 캐릭터 프로필 영역** | **캐릭터의 현재 감정에 따른 이미지** | **반영함** |
| **캐릭터 상세 화면의 프로필** | **캐릭터의 현재 감정에 따른 이미지** | **반영함** |

- **대화창에서는 발화 당시 감정, 현재 감정, 표정 스냅샷을 사용하지 않는다.** 대화 프로필은 과거·현재의 모든 메시지에서 항상 기본 이미지다.
- 표정 변화는 **고정 프로필 영역과 캐릭터 상세 화면 두 곳에서만** 일어난다.
- 이 요구를 위해 메시지별 감정 컬럼·대화 스냅샷·SSE 메시지 포맷을 추가하지 않는다.

## 3. 화면 상단의 새로운 고정 프로필 영역

현재 스크롤할 때 고정되는 `대화 / 캐릭터 / 세계관 설정` 메뉴가 있다. **그 메뉴 바로 아래에 연속해서** 새로운 캐릭터 프로필 영역을 만든다.

- 세계관에 속한 **활성 캐릭터 각각의 프로필 이미지와 이름**을 나열한다. 세계관 최대 캐릭터 수는 기존대로 6명이다.
- 메뉴와 프로필 영역은 스크롤 중 **함께 상단에 고정**되어야 하며 두 영역 사이에 틈이나 겹침이 없어야 한다.
- 상단 스택의 높이·`top`·`z-index`·배경·그림자 등은 기존 sticky 레이아웃을 조사하여 정합적으로 구현한다. 이중 sticky로 본문이 가려지지 않게 한다.
- 각 캐릭터의 이미지는 **현재 감정에 해당하는 표정 이미지**를 보여준다. 상태가 바뀌면 해당 캐릭터의 이미지가 갱신된다.
- 프로필을 누르면 **해당 캐릭터 상세 화면으로 이동**한다. 기존 라우팅/상세 진입 UX를 우선 재사용한다.
- 이름은 읽기 쉽게 표시하며, 모바일에서는 너비 부족 시 자연스럽게 가로 스크롤되는 프로필 목록 등을 적용한다. 상단 메뉴의 사용성을 방해하지 않는다.
- 이미지 크기·레이아웃은 컴팩트하게 구성하고 기존 아이보리·로즈 핑크 테마를 유지한다.
- 캐릭터가 없으면 빈 프로필 바를 불필요하게 표시하지 않는다.
- **감정·관계·기억 변화 수치를 대화 피드에 별도 메시지로 넣지 않는다.**

## 4. 감정 12종 → 표정 8종 매핑

| 현재 감정 | 파일 |
| --- | --- |
| `NEUTRAL`, `CALM` | `neutral.webp` |
| `HAPPY`, `EXCITED` | `happy.webp` |
| `HOPEFUL` | `hopeful.webp` |
| `SAD`, `LONELY` | `sad.webp` |
| `ANXIOUS`, `FEARFUL` | `anxious.webp` |
| `ANGRY` | `angry.webp` |
| `EMBARRASSED` | `embarrassed.webp` |
| `TIRED` | `tired.webp` |

- 하나의 공통 매핑 함수에서 관리한다.
- 상태의 출처는 **서버의 현재 캐릭터 감정 상태**다. 기존 SSE/갱신 메커니즘을 먼저 검토해 사용하고 중복 구독·불필요한 폴링을 만들지 않는다.
- 감정 상태가 없거나 알 수 없으면 `neutral.webp`로 표시한다.
- **표정 표시를 위해 AI 감정 계산 로직을 변경하지 않는다.**

## 5. 캐릭터 생성·편집 및 중복 금지

- 여성 캐릭터에는 여성 17종, 남성 캐릭터에는 남성 6종만 제공한다.
- 목록과 미리보기에서는 **항상 `neutral.webp`**를 보여준다.
- 처음 생성할 때 사용 가능한 일러스트 ID 중 랜덤 선택하되, 사용자가 직접 선택할 수 있다. 기존 랜덤·잠금 동작을 조사하여 충돌 없이 연동한다.
- **동일 세계관 내 활성 캐릭터의 `avatarId` 중복을 절대 허용하지 않는다.** 다른 세계관 사이에는 같은 ID를 사용할 수 있다.
- 사용 중인 이미지는 UI에서 표시·비활성화하고, 서버에서도 검증한다. 동시 생성/편집 경합에서도 중복이 발생하지 않게 기존 DB·트랜잭션 특성에 맞게 처리한다.
- 사망했지만 삭제되지 않은 캐릭터는 여전히 이미지를 점유한다. 기존 soft-delete 처리로 비활성화된 캐릭터의 이미지는 재사용 가능하다.
- 편집 중 자기 자신의 이미지는 유지/선택 가능하다. 성별 변경 시 유효한 미사용 이미지로 다시 선택해야 한다.
- 이미지가 소진되면 중복 허용 대신 명확한 안내·오류를 제공한다.
- 기존 캐릭터 편집 제한(실행 상태, 사망 등)은 그대로 유지한다.

## 6. 데이터·저장·불러오기

- 캐릭터에는 **이미지 파일 자체가 아닌 `avatarId`**를 저장한다.
- 데이터 검증: 존재하는 ID, 성별 일치, 동일 세계관 내 중복 금지.
- 과거 캐릭터의 `avatarId` 누락 및 기존 세이브의 호환성을 고려한다. 기본 표시·마이그레이션을 하면서 중복 사용이 발생하지 않도록 설계한다.
- 월드/게임 저장·불러오기 스냅샷에 `avatarId`가 일관되게 반영되어야 한다. 필요하다면 버전 및 마이그레이션 테스트를 추가한다.
- **대화 메시지별 표정 데이터는 저장할 필요가 없다.** 대화창은 항상 기본 표정이다.
- DB 스키마 변경이 필요하다면 최소 범위로 수행하고 기존 데이터 손실을 방지한다.

## 7. 상세 화면

- 캐릭터 상세 화면의 프로필에는 해당 캐릭터의 **현재 감정 표정**을 사용한다.
- 감정 변경 후 재조회/실시간 갱신 시 프로필도 최신 상태를 반영한다.
- 기존 상태창(감정·신체 막대, 최근 감정 변화, 관계, 기억), 강도별 로즈 색상, 편집 제한은 유지한다.

## 8. 스타일·접근성·성능

- 기존 앱 배경과 상단 메뉴 디자인은 불필요하게 변경하지 않는다.
- 모든 이미지 표시에서 비율을 유지하고 레이아웃 이동을 방지한다. 이미지 실패 시 기본 이미지/안전한 대체 표현을 제공한다.
- 프로필 아이템은 이름을 접근 가능한 텍스트로 제공하고 키보드 포커스/탭 이동이 가능해야 한다.
- 6명 내외 고정 프로필 갱신으로 불필요한 전체 대화 목록 리렌더링을 일으키지 않는다.
- 서버/클라이언트 컴포넌트 경계, 구독 해제 및 복구 경로를 기존 아키텍처에 맞춘다.

## 9. 테스트·완료 보고

다음 사례를 확인한다.

1. 여성 17종·남성 6종, 표정 파일 총 184개 검증
2. 생성·편집에서 항상 기본 이미지 표시
3. **과거·현재 모든 대사 프로필이 항상 기본 이미지인 것 확인**
4. 상단 고정 메뉴 **바로 아래** 프로필·이름 영역 노출 및 스크롤 중 고정
5. 프로필 선택 시 캐릭터 상세 진입
6. 고정 프로필과 상세 화면에서만 현재 감정 표정 변경
7. SSE/데이터 갱신·재접속 시 최신 표정 동기화
8. 동일 세계관 중복 선택·랜덤 중복·동시 생성·편집 차단
9. 다른 세계관의 동일 아바타 사용 허용, 사망/soft delete 점유 규칙
10. 저장·불러오기 및 과거 데이터 호환성
11. 모바일 가로 폭, sticky 겹침, 레이아웃·접근성
12. typecheck, lint, 관련 단위·통합 테스트 및 가능하면 실제 브라우저 검증

완료 후 구현한 기능, 변경 파일, DB/스냅샷 변경, 중복 방지 방식, 실시간 갱신 방식, 이미지 검증, 테스트 결과, 실제 브라우저 검증 여부, 남은 문제와 커밋 해시를 보고한다. **검증하지 못한 항목은 통과했다고 쓰지 않는다.**

> 기존의 성별값 NONBINARY·CUSTOM·UNSPECIFIED는 사용되지 않을것이기에 무시한다.

> 핵심 원칙: **캐릭터 생성/편집과 대화창 = 무조건 기본 이미지. 상단 고정 캐릭터 프로필 영역과 캐릭터 상세 = 현재 감정에 따라 표정 변화.**
